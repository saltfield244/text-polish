# 回帰テストと実機確認手順

対象: クリップボードの全形式退避・復元(v1.0.1 の不具合修正)、APIキーの暗号化保存、
ホットキーの連打・経路をまたいだ同時実行に対する排他。

## 自動テスト

外部NuGetパッケージを増やさない方針のため、xUnit等は使わず依存なしのコンソールアプリにしています。
失敗が1件でもあれば終了コード 1 を返します。

```
dotnet run --project src\TextPolish.Tests
```

- クリップボードのテストは**実際のクリップボードを書き換えます**。実行前の内容はテスト対象の
  `ClipboardSnapshot` で退避し、終了時に戻します。Windowsの「クリップボードの履歴」(Win+V)を
  有効にしている場合、テスト中の内容が履歴に残ります。
- デスクトップのない環境(CI、サービス実行等)では `--no-clipboard` を付けて設定のテストだけを実行します。
  ```
  dotnet run --project src\TextPolish.Tests -- --no-clipboard
  ```

| 区分 | 確認していること |
|---|---|
| 設定 | v1.0.1 の平文 `ApiKey` を3プロバイダとも暗号化して移行し、ファイルに平文が残らない |
| 設定 | 移行でAPIキー以外の設定(ホットキー・モデル名等)が変わらない |
| 設定 | テンプレートの `TODO-...` は暗号化せず、読み込みだけではファイルを書き換えない |
| 設定 | ファイルの `ApiKey` を直接書き換えた場合はそれが優先され、再暗号化される |
| 設定 | 設定画面からの更新・削除 |
| 設定 | 復号できない暗号文は、保存しても「削除」を押すまで消えない |
| 設定 | 別プロバイダの暗号文を書き写しても復号できない |
| 設定 | 保存に失敗しても元のファイルは変わらず、一時ファイルも残らない |
| 設定 | 5000文字のトークン・非ASCIIのキーの往復 |
| クリップボード | テキスト / テキスト+HTML+RTF / 画像 / ファイル一覧(切り取り・コピーの区別を含む) / 空 の復元 |
| クリップボード | サイズ上限を超えた場合は小さい形式(テキスト等)を優先して残す |
| 遅延復元 | 待ち時間後に元の内容へ戻る |
| 遅延復元 | 待機中にユーザーがコピーした内容を上書きしない |
| 遅延復元 | 連続実行しても、最後に残るのは最初の元内容 |
| 遅延復元 | アプリ終了時は待たずに復元する |
| 排他 | 保持中の再取得は失敗する(ホットキーの連打) |
| 排他 | 選択テキストの取得を始める前から保持する(パレットのウィンドウ生成を待たない) |
| 排他 | 即実行の整形中はパレットを起動しない / パレット表示中は即実行しない |
| 排他 | 例外・キャンセル・選択テキストなしのいずれでも解放される |
| 排他 | 二重解放しても、間に始まった操作の排他を解かない |
| 排他 | 交互操作を繰り返しても取りこぼさない |
| 排他 | 複数スレッドから同時に取得しても成功するのは1件 |

排他のテストは `OperationGate` と、App 側の呼び出し方(パレットは閉じるまで保持、即実行は
`finally` で解放)を模した流れを対象にしています。ホットキーのフックとWPFのウィンドウは
自動化できないため、実際のキー入力での挙動は下記 D の実機確認で見ます。

Ctrl+C/Ctrl+V の送出を伴う端から端までの動作(`SelectionCapture` / `ClipboardTextInserter`)は、
フォアグラウンドのウィンドウに依存して自動化が不安定になるため、下記の実機確認で見ます。

## Windows実機での確認手順

準備: `dotnet build` したアプリ(または publish した配布物)を起動し、ログ
(`%AppData%\TextPolish\logs\`)を開いておく。メモ帳とエクスプローラー、ペイント、Word か ブラウザを使う。

### A. クリップボードの保持

各項目とも「整形パレットで整形して書き戻す」と「即実行ホットキー」の両方で確認する。
書き戻しの約1秒後(`RestoreDelayMs`)に、元の内容に戻っていることを確かめる。

| # | 操作前にクリップボードへ入れるもの | 確認方法 | 期待結果 |
|---|---|---|---|
| A1 | メモ帳でコピーしたテキスト | メモ帳に貼り付け | 元のテキストが貼り付く |
| A2 | Snipping Tool / PrtScn の画像 | ペイントに貼り付け | 元の画像が貼り付く |
| A3 | エクスプローラーで「コピー」したファイル2つ | 別フォルダで貼り付け | 2つともコピーされる |
| A4 | エクスプローラーで「切り取り」したファイル | 別フォルダで貼り付け | **移動**になる(コピーにならない) |
| A5 | ブラウザ/Wordで書式付きの文章をコピー | Wordに貼り付け | 太字・リンク等の書式が残る(HTML/RTF) |
| A6 | Excel のセル範囲 | Excel に貼り付け | セル範囲として貼り付く |
| A7 | クリップボードを空にする(`powershell -sta -c "Add-Type -A System.Windows.Forms; [Windows.Forms.Clipboard]::Clear()"`) | メモ帳で Ctrl+V | 何も貼り付かない |
| A8 | テキストを選択せずにホットキー | — | 「テキストが選択されていません」の通知。クリップボードは元のまま |

### B. 復元待ち中の競合

| # | 操作 | 期待結果 |
|---|---|---|
| B1 | 設定の `RestoreDelayMs` を 5000 にする。即実行で書き戻した直後(5秒以内)に、別のテキストを Ctrl+C | 5秒後もクリップボードは自分がコピーしたテキストのまま。ログに「復元は見送りました」 |
| B2 | (B1の設定のまま) 元の内容Xをコピー → 即実行 → 5秒以内にもう一度即実行 | 最終的にクリップボードはX(整形結果1が残らない)。ログに「復元待ちを引き継ぎます」 |
| B3 | (B1の設定のまま) 即実行の直後にトレイから終了 | 終了後のクリップボードは元の内容 |
| B4 | `RestoreDelayMs` を 800 に戻し、整形結果が正しく貼り付くこと(元の内容が誤って貼り付かないこと)を数回確認 | 整形結果が貼り付く(v1.0.1と同じ) |
| B5 | 4K画面全体のスクリーンショットをコピーしてから即実行 | 体感で遅くならない。画像が戻る |

### C. APIキーの暗号化保存

| # | 操作 | 期待結果 |
|---|---|---|
| C1 | v1.0.1 で平文のキーを保存済みの `appsettings.json` をそのまま使って起動 | ログに「平文のAPIキーを暗号化して保存し直しました」。ファイルの `ApiKey` は `""`、`ApiKeyProtected` が `dpapi:v1:...`。整形できる |
| C2 | C1の後に再起動 | 整形できる(復号できている)。ファイルは変化しない |
| C3 | 設定画面を開く | 3プロバイダとも保存済みのキーが(マスク表示で)入っている |
| C4 | キーを変更して保存 → 整形 | 新しいキーで動く。ファイルに新しいキーの平文がない |
| C5 | 「削除」→ 保存 | そのプロバイダの `ApiKeyProtected` が消える |
| C6 | 別のWindowsユーザーで C1 のファイルを使って起動 | 起動時に「APIキーを読み出せませんでした」の通知。設定画面に赤字の警告。何も入力せず保存しても `ApiKeyProtected` は残る |
| C7 | `appsettings.json` を読み取り専用にして v1.0.1 の平文ファイルで起動 | ログに「暗号化保存に失敗」。ファイルは平文のまま変わらず、整形はできる。読み取り専用を外して再起動すると移行される |
| C8 | 配布用の `appsettings.json`(TODO- のまま)で起動 | ファイルが書き換わらない(コメントが残る) |

移行後も、ディスクの空き領域やバックアップ・OneDriveの版履歴・ボリュームシャドウコピーには
平文の旧ファイルが残っている可能性があります。キーが漏れた可能性を排除したい場合は、
移行後にプロバイダ側でキーを再発行(ローテーション)してください。

### D. ホットキーの連打・同時実行

準備: ログ(`%AppData%\TextPolish\logs\`)を開いておく。無視された操作は
「ほかの操作(…)が実行中のため、…を無視しました。」としてログに残る。
D3・D4 は差が見えるよう、LLMの応答が数秒かかるモデル・長い文章で試す。

| # | 操作 | 期待結果 |
|---|---|---|
| D1 | メモ帳でテキストを選択し、パレットのホットキーを素早く3回押す | パレットは1つだけ開く。ログに「整形パレットを無視しました」が2件。メモ帳の選択・クリップボードの内容は壊れない |
| D2 | テキストを選択し、即実行のホットキーを素早く3回押す | 整形・書き戻しは1回だけ。ログに「即実行を無視しました」が2件。整形結果が二重に貼り付かない |
| D3 | テキストを選択して即実行 → 整形中(トレイが「…で整形中...」)にパレットのホットキーを押す | パレットは開かない。即実行の書き戻しが正常に完了する。ログに「整形パレットを無視しました」 |
| D4 | パレットを開いた状態で即実行のホットキーを押す | 何も起こらない。ログに「即実行を無視しました」。パレットはそのまま使える |
| D5 | パレットを開いた状態でパレットのホットキーを押す | パレットが前面に出るだけ(新しく開かない) |
| D6 | パレットの選択テキスト取得中(押してすぐの0.1秒以内)に、即実行のホットキーを押す | 即実行は無視される。Ctrl+C の送出は1回だけで、パレットには選択したテキストがそのまま入る |
| D7 | テキストを選択せずにパレット/即実行のホットキーをそれぞれ3回押す | 毎回「テキストが選択されていません」の通知が出る(排他が残って2回目以降が無反応にならない) |
| D8 | APIキーを誤った値にして即実行 → エラー通知が出たあと、もう一度即実行 | 2回目も通知が出る(例外で排他が残らない) |
| D9 | パレットを開き、整形を実行してから結果を適用せずに閉じる → 即実行 | 即実行が動く(パレットを閉じた時点で解放されている) |
| D10 | パレット→即実行→パレット→即実行を10回繰り返す | 毎回動く。無視のログが出ない。クリップボードは元の内容に戻る |
| D11 | 即実行の整形中にトレイから設定画面を開き、保存して閉じる | 即実行は完了する。閉じたあとのホットキーが効く |
| D12 | 即実行の整形中にトレイから終了 | 終了できる。クリップボードは元の内容に戻る(`OnExit` の即時復元) |
