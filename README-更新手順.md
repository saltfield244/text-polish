# TextPolish - 既存利用者の更新手順(ポータブルZIP)

v1.0.1 以前から更新する人向けの手順です。新規インストールは
**README-インストール手順.txt** を参照してください。

配布形式はフォルダを展開して使うポータブルZIPで、インストーラもレジストリも使いません。
そのため更新は「フォルダの中身を入れ替える」操作になりますが、**ZIPをそのまま上書き展開すると
設定が消えます**。下記の手順で、残すファイルを先に退避してください。

---

## 1. 上書きしてはいけないファイル

展開先フォルダ(`TextPolish.exe` と同じ場所)にある次の3つは、利用者が設定・編集するものです。
ZIPにも同名のファイルが入っているため、素直に上書きすると初期状態に戻ります。

| ファイル | 中身 | 失うと |
|---|---|---|
| `appsettings.json` | APIキー・ホットキー・プリセット・LLMプロバイダの設定 | APIキーとプリセットを入れ直すことになる |
| `Glossary.txt` | 用語辞書(誤変換されがちな表記 → 正しい表記) | 育ててきた辞書が消える |
| `PolishSystemPrompt.txt` | 整形の共通方針(システムプロンプト) | 手を入れていた場合、その調整が消える |

ログは別の場所(`%AppData%\TextPolish\logs\`)にあるため、更新の影響を受けません。
自由指示の履歴も同じ `%AppData%\TextPolish\` 配下なので残ります。

ただし **v1.0.1 以前に書かれたログは残したままにしないでください。** 整形に失敗したときに
LLMの応答本文(整形を依頼した文章を含むことがあります)がログへ記録される問題があったためです。
この問題は v1.0.2 で修正済みですが、すでに書かれたログは消えません。更新後に
`%AppData%\TextPolish\logs\` の中身を削除してください(アプリの動作には影響しません)。

## 2. 更新手順

### 手順A: 退避して入れ替える(推奨)

```
1. トレイアイコンを右クリック →「終了」でアプリを終了する
   ※ 起動したままだと TextPolish.exe を置き換えられません。
```

```
2. 今のフォルダにある次の3ファイルを別の場所へコピーして控えを作る
     appsettings.json / Glossary.txt / PolishSystemPrompt.txt
   ※ この控えの役目は**設定を残すこと**で、戻る先の実行ファイルを残すことではありません。
      更新がうまくいかなかったときは、v1.0.2 を展開し直してこの3ファイルを戻します
      (「7. 更新を中止したいとき」)。更新前のフォルダ(v1.0.1)へ戻って使い続けることは、
      配布を取り下げた版を動かすことになるため通常の復旧手段にはしません。
   ※ 控えの `appsettings.json` には**平文のAPIキー**が入っています。手順7で削除し、
      APIキーの再発行も行ってください(「3. APIキーについて」)。
```

```
3. 新しい ZIP を別の空フォルダへ展開する
   ※ ZIPのプロパティに「セキュリティ: このファイルは…」が出ていたら、
      展開前に「許可する」にチェックを入れてください。
```

```
4. 展開した新しいフォルダから、次の3ファイルを削除する
     appsettings.json / Glossary.txt / PolishSystemPrompt.txt
```

```
5. 控え(手順2)から同じ3ファイルを、新しいフォルダへコピーする
```

```
6. 新しいフォルダの TextPolish.exe を起動し、動作を確認する
   ・トレイに常駐すること
   ・テキストを選択してホットキーを押すと整形できること
   ・設定画面にAPIキーが(マスク表示で)入っていること
```

```
7. 問題なければ、更新前のフォルダと控えを削除する
   ※ どちらの `appsettings.json` にも**平文のAPIキー**が入っています
      (暗号化されるのは v1.0.2 が保存し直したファイルだけです)。確認が済んだら残さず削除し、
      APIキーの再発行も済ませてください(「3. APIキーについて」)。
   ※ 更新前のフォルダは配布を取り下げた v1.0.1 です。すぐ起動できる状態で残さないでください。
```

スタートアップに登録している場合は、ショートカットの参照先を新しいフォルダへ向け直してください。

### 手順B: ソースからビルドして使っている場合

`dotnet publish` は `appsettings.json` も上書きします(`CopyToOutputDirectory=PreserveNewest`)。
publish 前に退避し、publish 後に戻してください。詳細は
**README-ソースからのビルド手順.md** の「ソースを直したのにアプリの挙動が変わらない」を参照してください。

## 3. APIキーについて(v1.0.2 で変わる点)

v1.0.2 から、APIキーは **DPAPI(Windowsのデータ保護API)で暗号化**して
`appsettings.json` の `ApiKeyProtected` に保存します。平文の `ApiKey` は空になります。

- **同じPC・同じWindowsユーザーで更新する場合**: 何もする必要はありません。
  v1.0.1 の平文のキーは、初回起動時に自動で暗号化して保存し直されます(ログに記録されます)。
- **別のPCや別のWindowsユーザーへ移す場合**: 暗号化されたキーは**復号できません**。
  DPAPIはWindowsユーザー単位で鍵を管理するためです。起動時に
  「保存済みのAPIキーを読み出せませんでした」と通知されるので、設定画面でキーを入力し直してください。
  `appsettings.json` のその他の設定(ホットキー・プリセット・モデル名)はそのまま使えます。
- **v1.0.1 以前を使っていた場合は、更新後にプロバイダ側でAPIキーを再発行(ローテーション)してください。**
  任意の作業ではなく、更新の一部として扱ってください。v1.0.1 までのキーは `appsettings.json` に
  平文で保存されていたため、バックアップ・OneDriveの版履歴・ボリュームシャドウコピー・
  ディスクの空き領域に残っている可能性があり、ファイルを消しても消えたとは言い切れません。
  手順はプロバイダによりますが、**新しいキーを作る → 設定画面で入れ替える → 古いキーを無効化(revoke)する**
  の順で行います。古いキーを先に無効化すると、入れ替えるまで整形が失敗します。

## 4. 更新後に確認すること

| # | 確認 | 期待 |
|---|---|---|
| 1 | アプリが起動し、トレイに常駐する | 「待機中」になる |
| 2 | 設定画面を開く | 3プロバイダともAPIキーが入っている(マスク表示) |
| 3 | テキストを選択してホットキー → 整形 → 置き換える | 選択範囲が整形結果に置き換わる |
| 4 | 整形前にコピーしていた内容を貼り付ける | 元の内容が戻っている |
| 5 | プリセットの一覧 | 自分が編集した内容のまま |
| 6 | 用語辞書が効いている | 辞書に書いた表記に直る |
| 7 | 設定画面の「LLMへ送る範囲」 | **オフになっている**(下記参照) |

ログ(`%AppData%\TextPolish\logs\`)に `Error` が出ていないかも確認してください。
確認を終えたら、v1.0.1 以前に書かれた分を含めてログを削除し(1を参照)、
APIキーの再発行(3を参照)も済ませてください。

## 6. うまくいかないとき

### 起動時に「保存済みのAPIキーを読み出せませんでした」と出る
`appsettings.json` を別のPCまたは別のWindowsユーザーからコピーしています。
設定画面でキーを入力し直してください(上記3を参照)。

### 整形の精度が落ちた気がする
周辺文脈の送信が既定でオフになったためかもしれません。
設定画面の「LLMへ送る範囲」をオンにして比べてみてください。

### 設定が初期状態に戻った
`appsettings.json` を上書きしています。控えの3ファイルを戻してください
(「7. 更新を中止したいとき」のA)。控えを取っていない場合はAPIキーの再入力が必要です。

### 古いバージョンに戻したい
v1.0.1 以前へ戻すことは勧めません。配布を取り下げた版です。
設定を失わずに更新を中止・やり直しする方法は「7. 更新を中止したいとき」にまとめました。
それでも旧版を使わざるを得ない場合の注意事項は、同節のDにあります。

## 7. 更新を中止したいとき(安全な復旧)

更新がうまくいかなかったときの戻り先は、**更新前のフォルダ(v1.0.1)ではありません。**
v1.0.0 / v1.0.1 は配布を取り下げた版で、APIキーが平文で保存される問題と、整形に失敗したときに
LLMの応答本文がログへ記録される問題があります。機能としては動きますが、安全に動く状態ではありません。

設定・プリセット・用語辞書は `appsettings.json` / `Glossary.txt` / `PolishSystemPrompt.txt` の
3ファイルに入っていて、どのバージョンの実行ファイルからも独立しています。
**この3ファイルの控えがあれば、実行ファイルを入れ替えても設定は失われません。**
復旧は上から順に検討してください。

### A. 更新をやり直す(まずこれ)

```
1. トレイアイコンを右クリック →「終了」でアプリを終了する
```

```
2. 新しいZIPを別の空フォルダへ展開し直す
   ※ 失敗したフォルダに上書きせず、新しい空フォルダへ展開してください。
      取り違えたファイルを持ち込まないためです。
```

```
3. 展開した appsettings.json / Glossary.txt / PolishSystemPrompt.txt を削除する
```

```
4. 控え(「2. 更新手順」手順Aの2)から同じ3ファイルをコピーする
```

```
5. 起動して「4. 更新後に確認すること」をやり直す
```

展開の取りこぼし、アプリを終了せずに上書きしたこと、3ファイルの戻し忘れが原因の失敗は、
これで直ります。APIキー・プリセット・用語辞書は控えから戻るため失われません。

### B. いったん使うのをやめる(いちばん安全)

TextPolish は常駐していなくても、ほかのアプリの動作には影響しません。
原因が分かるまでアプリを終了したままにしておくのが、最も安全な状態です。
3ファイルの控えを残しておけば、v1.0.2 の問題が解決したときに設定はそのまま戻せます。

症状(操作・通知の文面・`%AppData%\TextPolish\logs\` の `Error` 行)を
[Issues](../../issues) に書いていただけると助かります。
ログを添付する場合は、整形した文章が載っていないか目を通してください。

### C. ソースからビルドして使う

セキュリティ上の修正はどちらも `main` に入っています。ZIPの展開ではなく v1.0.2 の中身が
環境に合わない場合は、`main` をビルドして使う方法があります。
手順は **README-ソースからのビルド手順.md** を参照してください。
この場合も設定の3ファイルの扱いは同じです(「2. 更新手順」手順B)。

### D. やむを得ず v1.0.1 を一時的に使う(最後の手段)

A〜Cが取れず、どうしても旧版で作業を続ける必要がある場合に限ります。
取り下げた版を動かすことになるため、次を守ってください。

- **本番用のAPIキーを入れないでください。** v1.0.1 は入力したキーを `appsettings.json` へ
  平文で保存します。使うなら利用上限を絞った**使い捨てのキー**を新しく作り、
  v1.0.1 を使い終えた時点で無効化(revoke)してください。
- v1.0.2 が保存した `appsettings.json` を v1.0.1 で読むと、`ApiKeyProtected` は無視され
  `ApiKey` が空のため、キーの入力を求められます。ここで入れたキーが平文で書かれます。
  **v1.0.2 用の `appsettings.json` をそのまま使わせず、別フォルダへコピーを渡してください。**
  v1.0.1 が書いた平文のキーが、v1.0.2 側のファイルへ混ざらないようにするためです。
- **機密を含む文章の整形には使わないでください。** 整形に失敗したときに、依頼した文章を含む
  LLMの応答本文が `%AppData%\TextPolish\logs\` へ記録されることがあります。
  ログの場所は v1.0.2 と同じです。使い終わったら中身を削除してください。
- クリップボードの復元と書き戻し先の検証も v1.0.1 では不完全です。整形前にコピーしていた内容が
  戻らないこと、整形中に切り替えた別のウィンドウへ書き戻ることがあります。
  重要な入力欄やパスワード欄のあるアプリでは使わないでください。
- v1.0.2 へ移れたら v1.0.1 のフォルダを削除し、**APIキーを再発行**してください
  (「3. APIキーについて」)。使い捨てのキーを作っていた場合も、それとは別に
  v1.0.1 時代に使っていたキーの再発行が必要です。
